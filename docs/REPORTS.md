# SQL-аналитика и сравнение периодов

GET /api/analytics сохраняет прежний контракт. GROUP BY/SUM/COUNT выполняются в БД; отдельные операции не загружаются в Python. Месячная группировка использует ISO-дату и работает в SQLite/PostgreSQL; категории расходов группируются отдельным запросом. В обоих запросах проверяются владелец операции и категории. Суммы остаются целыми копейками; PostgreSQL SUM(BigInteger) преобразуется из Decimal в int без float.

GET /api/analytics/compare?start=YYYY-MM-DD&end=YYYY-MM-DD возвращает current, previous, current_period, previous_period и changes для доходов, расходов и разницы. Периоды включают обе границы и содержат одинаковое число дней; предыдущий заканчивается за день до текущего. Это не обязательно предыдущий календарный месяц. Delta — текущая сумма минус предыдущая; процент делится на модуль предыдущей суммы, при нуле возвращается null. Недопустимые границы и выход за диапазон дат дают400. Сравнение выполняет четыре агрегатных запроса; при конкурентной записи между ними возможен сдвиг данных, строгий снимок отчёта не гарантируется.

GET /api/analytics/monthly.csv экспортирует только агрегированный месячный отчёт. pandas используется для формирования CSV из небольшого набора месячных агрегатов, а не загрузки всей истории. Авторизация и фильтр владельца применяются и к экспорту. Интерфейс показывает предыдущие значения, абсолютные изменения и экспорт.

Тесты проверяют границы/високосный год, нулевую и отрицательную базу, точность сумм и число операций, четыре GROUP BY-запроса без выборки операций, доступ к чужому отчёту/экспорту и отсутствие доступа после выхода. PostgreSQL-сценарий проверяется в CI на Python3.12–3.14. Ruff E9/F проверяет app/tests/scripts; strict mypy пока проверяет app/periods.py.
