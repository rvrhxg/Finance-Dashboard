# Схема Ledger

Alembic 0001 создаёт исходную схему, 0002 добавляет `(user_id, occurred_on)` для запросов по владельцу и периоду. `python -m alembic upgrade head`, `current`, `history` и `check` выполняются из корня проекта. DATABASE_URL задаётся окружением; по умолчанию SQLite ledger.sqlite. Docker содержит конфигурацию и версии миграций.

Для однопроцессного MVP database() вызывает upgrade head при запуске и seed. При нескольких экземплярах миграции должны выполняться отдельным deployment job до старта приложения: конкурентный запуск миграций не поддерживается.

Старая база от предыдущей версии: остановите приложение, сохраните backup, сверяйте исходную схему с 0001. Только при точном соответствии выполните `python -m alembic stamp 0001`, затем `python -m alembic upgrade head` и `python -m alembic check`. Stamp записывает номер, не проверяет и не исправляет произвольную схему. Автоматического распознавания старой базы нет. Downgrade до base удаляет таблицы и данные; для реальных данных нужен проверенный backup/restore-план.

Тест проводит 0001 → 0002 → 0001 → 0002 с сохранением операции и сверкой моделей. PostgreSQL-тест создаёт отдельную схему, выполняет миграции и проверяет точные суммы BigInteger и владельцев. Это не проверка аварийного восстановления production-базы.
