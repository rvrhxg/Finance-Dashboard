# Архитектура Ledger

Самостоятельный Python-проект портфолио: FastAPI и Pydantic проверяют запросы, SQLAlchemy работает с PostgreSQL, pandas строит помесячные и категорийные группировки. JavaScript показывает графики и формы без сторонних CDN. SQLite используется в быстрых тестах.

User владеет Category, Transaction и Budget. Категория имеет тип income/expense, операция ссылается на неё. Сервер проверяет владельца категории при создании операции и бюджета; запросы чтения/удаления фильтруются по user_id. Cookie содержит случайный токен, в БД хранится SHA-256; пароль — scrypt с солью.

API принимает сумму строкой, Decimal преобразует её в целые копейки без округления дробных копеек. NaN/Infinity, bool, float, ноль и отрицательные суммы отвергаются. Transaction/Budget используют BigInteger; pandas группирует целые значения, а общие итоги считает Python. Доля сбережений — процент для отображения; без доходов возвращается null. Разница за период не является остатком банковского счёта.

Период включает обе границы. Категорийная структура показывает только расходы; бюджеты привязаны к календарному месяцу и категории расходов. Список последних операций не ограничивает агрегаты: аналитика читает все операции владельца в выбранном периоде.

CSV валидируется полностью до записи: строгий набор колонок, предел строки/файла, даты, типы, категории и суммы. Внешний ID уникален для пользователя. Повтор с одинаковыми данными пропускается, конфликт содержимого отклоняется; внешняя транзакция откатывает весь импорт. Категории создаются внутри той же транзакции. Удалённая импортированная операция может быть восстановлена повторным импортом — это текущее поведение, без tombstone-журнала.

Ограничения: RUB без конвертации валют, нет банковских подключений, инвестсоветов и бухгалтерской отчётности; списки до 500 операций, аналитика пока загружает данные периода в память; нет миграций и восстановления пароля. Перед большим объёмом нужны SQL-агрегации, постраничная выдача, общий limiter и ограничение параллелизма scrypt.
